## The rules

| # | Rule | Why |
|---|---|---|
| R1 | **One agent, one worktree, one branch.** `git worktree add <path> -b <type>/<slug> origin/main`. Do not work directly in the shared checkout. | The shared checkout has other sessions' uncommitted work in it. **This is the rule that matters most and the only one no hook can enforce.** |
| R2 | **Branch from `origin/main`, never local `main`.** `git fetch origin` first. | Local `main` goes stale fast in repos with bot commits. |
| R3 | **Stage explicit paths. Never `git add -A`, `git add .`, or a directory sweep.** Check `git diff --cached --name-only` before committing. | CAPA-005, CAPA-009. Enforced by hook (and globally). |
| R4 | **Check `git branch --show-current` immediately before every commit.** No commits on `main`. | Enforced by hook. |
| R5 | **Short-lived branches — land within a day or two.** | Long branches accumulate conflicts on files you never touched. |
| R6 | **Leave the shared checkout as you found it.** Remove your worktree when done; never `checkout`/`switch` there with a dirty tree. | A branch switch drags another session's work onto your branch. Enforced by hook. |

| R8 | **One merge at a time; verify `main` after landing.** | |
| R9 | **The reviewer is not the writer.** | Self-review finds nothing. |

## What the hook does and does not cover

`.claude/hooks/git-guard.sh`, wired in `.claude/settings.json`, blocks R3, R4
and R6. It fails open on anything it cannot parse.

**It does not cover the most common collision.** Two sessions editing the
*same file* and one of them staging that file by explicit path is a legitimate
`git add` — no guard can distinguish it from correct work. That case is
prevented by R1 and nothing else.
